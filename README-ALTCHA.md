# MTM Enterprises — self-hosted ALTCHA security update

## Contents
This is a **patch**, not a replacement repository. Based on the latest project files available in this conversation. Back up and review diffs first.

- React contact form and 3D quote form now use a local ALTCHA widget instead of Cloudflare Turnstile.
- Express generates 5-minute signed challenges at `GET /api/security/altcha?purpose=contact|quotes`, validates submitted proofs, checks purpose, and records consumed proofs in MongoDB with a unique index for cross-replica replay protection.
- Existing honeypot, 15-character / letter-based description validation, rate limits (3 contact / 15 min, 3 quote / hour), and 100 MB uploads are retained.
- The ALTCHA secret is mandatory (fail closed). No outbound CAPTCHA API calls or Cloudflare account needed.

## Apply and build on Windows
1. Extract the ZIP at the repository root. Review `git diff` before commit. Back up custom modifications.
2. `cd server && npm install` then `cd ../client && npm install && npm run build`.
3. Test form submissions, including attempts with no proof, an expired proof, and replaying a proof. The update should reject invalid requests **before** creating inquiries/quotes.
4. Commit the changes, including updated package-lock files generated by npm install, then push through the existing GitHub Actions -> Argo CD process.

## MicroK8s secret (required BEFORE deploying the new API)
Run on Ubuntu. This generates a random secret and installs it in the mtm-mern namespace:

```bash
SECRET=$(openssl rand -hex 32)
sudo microk8s kubectl -n mtm-mern create secret generic mtm-altcha \
  --from-literal=ALTCHA_HMAC_SECRET="$SECRET" \
  --dry-run=client -o yaml | sudo microk8s kubectl apply -f -
unset SECRET
```

Helm `altchaSecretName: mtm-altcha` points the API Deployment at this Secret. The Secret must persist across restarts. Do NOT commit it, log it, or regenerate it during normal deploys: rotating invalidates outstanding challenges.

For local Windows development, set `ALTCHA_HMAC_SECRET` in `server/.env` (a random 64-character hex string); keep `.env` out of Git.

## Verify

```bash
sudo microk8s kubectl -n mtm-mern rollout status deployment/mtm-api
curl -s https://mtm-ent.org/api/security/altcha?purpose=contact
```

The response should be signed challenge JSON. In a private browser window, submit a legitimate contact message, then a 3D quote and confirm they appear in the dashboard. Test an empty security proof: should return HTTP 403, not create a record. Check `sudo microk8s kubectl -n mtm-mern logs deployment/mtm-api --since=10m` for errors.

If you are using a different live API deployment name, adjust the kubectl command; do not rename your deployment to match this README.

## Security notes
- Rate limiting is per API replica using the default in-memory store. With multiple API replicas, migrate to a shared limiter store. Nginx proxy headers and Express `TRUST_PROXY_HOPS` must be configured to trust only known proxies; never blindly trust arbitrary client X-Forwarded-For values.
- Uploaded 100 MB files are still buffered in memory. Multiple simultaneous large uploads can stress the API container; implement streaming and resource quotas for long-term resilience.
- The signed puzzle is not a guarantee that a visitor is human. Honeypot, validation, rate limiting, and moderation are complementary.
- No Cloudflare credential is used. Remove old `TURNSTILE_*` keys after confirming the new deployment works.
- Review `client/nginx.conf` and Ubuntu Nginx body-size limits if uploads fail (frontend and host should permit ~110 MB multipart requests).
- The `altcha` and `altcha-lib` packages need a fresh `npm install`; this patch does not bundle node_modules.
